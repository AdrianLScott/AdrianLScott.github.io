Treat model output as untrusted input

Every response is parsed and validated against a closed schema. Anything off-contract fails loudly instead of writing bad data.

Keep AI on the server

The app sends audio or text; only the backend talks to OpenAI. No keys in the bundle, and the model can change without an app release.

Constrain, then default

Fixed category and payment enums, temperature 0, and explicit fallbacks ("Other", "Cash") when the user leaves something out.

Capture without friction

A home-screen widget with a two-state recording flow, so logging a purchase takes seconds and never requires opening the app.

The parser, its guardrails and a 30-case eval set (Spanish and English, including Whisper hallucinations it must reject) are public in controla-ai-parser, with 34 offline tests. Next: run the evals in CI on every prompt change.

How I work with AI agents

Guardrails before generation

On a production operations system I built for a small business (catalog, manufacturing, purchasing and sales), I set up the repository so AI agents work inside clear rules. Each module has documented invariants and a playbook, and every change has to declare its blast radius before any code is written. Business details are private, so here is the pattern.

# AI Working Agreement
Before changing any module, read that module's invariants and playbook docs first.

## Pre-change Checklist (Mandatory)
For any implementation task, the assistant must state:
1. Which module is being changed.
2. Which entities/tables are impacted.
3. Which service/function boundary will handle writes.
4. Whether stock/pricing/BOM side effects are involved.

If unclear, ask for clarification before coding.

Result: 48 test files, versioned database migrations, and architecture decision records, so speed from AI never meant losing track of business rules.
